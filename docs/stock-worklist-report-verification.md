# Stock worklists and consistent loss-report pages

October 27, 2026. Test quantities and costs below are synthetic. This follow-up changes access to unresolved records and report-page consistency; it does not certify physical stock, establish the cause of the historic reported shortage or replace cashier-PC endurance checks.

## Problems and resulting behavior

The stock-control command returned only the oldest fifty open holds and pending issues. The interface had no next page or full count. A blocked old issue could leave newer work inaccessible without acting on the old records first. The new read-only command extension returns fifty rows, an exact timestamp/UUID continuation and full current branch counts. Inventory can load additional held goods and pending issues independently, retains loaded rows on failed requests and exposes the completed worklist. Successful stock actions refresh from the first page so removed or changed quantities do not stay presented as current.

Loss reports retained their previously loaded rows after a failed filter change, but further pages combined the retained timestamp/cursor with the newly requested filters. That could mix categories, dates or branch scope in loaded rows and CSV. Further loss/reconciliation pages now use the retained report's own filters and snapshot. A notice continues to identify the retained report until the requested filters load successfully. Totals, displayed snapshot and exported loaded rows remain tied to the same report. Changing documentary cost still requires its existing owner authorization, expected version, original request ID and immutable evidence.

The migration changes a read-only stock-control response, using the existing held/pending worklist indexes. It delegates to the unchanged command chain before reading, preserving current session, active organization/branch membership and prohibited-cashier checks. Old command execution stays private; no table permissions, stock mutations, cash writes, prices, dependencies or history rules are broadened.
