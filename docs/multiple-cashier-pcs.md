# Multiple cashier PCs

The November 4 user decision requires simultaneous checkout on several PCs. Enabling multiple-PC mode requires owner access, a reason and no open branch shifts. Each authorized owner/manager can then register another PC without retiring the existing ones. The existing unique open-shift-per-device rule remains; each drawer keeps its opening cash, payments, returns and closing count.

This mode requires internet for cash as well as credit. The server serializes shared branch stock and validates aggregate product/lot quantities before committing cash receipts, payments and movements in one transaction. A stale basket with insufficient stock is rejected without a financial record; it remains editable. Older offline-only clients cannot open/renew these shifts and cannot submit new cash sales through the old endpoint. Explicit owner recovery of genuine original offline history remains available; it must not be used for new checkout.

Cash requests are saved to the local online-operation journal before submission. An interrupted outcome has no success receipt and locks basket editing/payment-type changes until its original reference is confirmed. Retrying after reload, importing a recovery file or replaying the same request cannot create another sale/payment. Server confirmation and a local confirmed receipt are committed atomically with removal of the pending operation. Receipts keep the existing 58 mm format and peso line discounts.

Owner steps: synchronize and close all existing shifts, update the app on each profile, then Settings → Cashier PCs → Enable multiple cashier PCs. Sign in online on each PC; an owner or manager performs its initial registration. Use a distinct normal browser profile per physical PC and a separately counted drawer. Do not copy a profile/PC image containing an active device identity. Cashiers need existing branch access; this mode grants no employee permissions. Verify physical opening stock, prices and units before selling. Stop checkout during outages and retry original uncertain requests after reconnecting.

Closing one drawer does not close another. Stock counting and starting-balance review still require all branch shifts closed. Returning to single-PC mode requires all shifts closed and all but one PC retired; the command enforces this even though the owner screen only offers activation. App updates, devices, account creation and backups remain separate acceptance requirements.

Verification: local unit coverage includes online-only offline rejection, durable interrupted requests, malformed acknowledgements, recovery-file replay and authoritative rollback. Database tests cover activation guards, old-client refusal, two simultaneous shifts, shared-stock rejection, idempotency and independent drawer closing. Disposable signed-in browser tests cover two isolated profiles racing discounted cash sales, real server rollback, offline pause, a committed response lost before reload and the original receipt retry. No invented transactions are submitted to production.
